import { TabItem, Tabs } from "@astrojs/starlight/components";

Express 4.18 or later, 5 included, with Prisma 7 and `@prisma/adapter-pg`. Each response carries
`X-Debug-Token`, and `/_profiler` shows every request. Three steps, and nothing to remove before
deploying. A complete app is in
[`examples/express`](https://github.com/josemojena/query-profiler/tree/main/examples/express).

## 1. Install it, and run the dev server with the `development` condition

Without a bundler there is no build step to swap the profiler out. Install it as a regular
dependency and import it as usual: plain `node`, as in production, loads the entry that does
nothing. Or keep it **development only**: a dev dependency the app imports only if it is installed,
so a production install (`npm ci --omit=dev`) leaves it out. Pick one below; the steps follow it.
With a bundled server, see [installation](/docs/installation#a-bundled-server).

<Tabs syncKey="install">
  <TabItem label="As a dependency">

```sh
npm i query-profiler
```

  </TabItem>
  <TabItem label="Development only">

```sh
npm i -D query-profiler
```

  </TabItem>
</Tabs>

Either way, Node loads the real code only when started with `--conditions=development`:

```json
{
  "scripts": {
    "dev": "tsx watch --conditions=development src/server.ts",
    "start": "node dist/server.js"
  }
}
```

## 2. Profile the Prisma client

The same as in any app: see [Prisma](/docs/guides/prisma).

<Tabs syncKey="install">
  <TabItem label="As a dependency">

```ts
// src/db.ts
import { PrismaPg } from "@prisma/adapter-pg";
import { profilePrisma, withProfiler } from "query-profiler/prisma";
import { PrismaClient } from "./generated/prisma/client.js";

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL });

export const prisma = profilePrisma(new PrismaClient(withProfiler({ adapter })));
```

  </TabItem>
  <TabItem label="Development only">

```ts
// src/db.ts
import { PrismaPg } from "@prisma/adapter-pg";
import { PrismaClient } from "./generated/prisma/client.js";

const adapter = new PrismaPg({ connectionString: process.env.DATABASE_URL });
// A dev dependency: a production install leaves it out, and the client stays plain.
const profiler = await import("query-profiler/prisma").catch(() => undefined);

export const prisma: Omit<PrismaClient, "$on"> = profiler
  ? profiler.profilePrisma(new PrismaClient(profiler.withProfiler({ adapter })))
  : new PrismaClient({ adapter });
```

  </TabItem>
</Tabs>

## 3. Add the middleware, first

Before any other middleware. This one also prints one line per request in the terminal:

<Tabs syncKey="install">
  <TabItem label="As a dependency">

```ts
// src/server.ts
import express from "express";
import { formatProfile } from "query-profiler";
import { profilerMiddleware } from "query-profiler/express";

const app = express();
app.use(profilerMiddleware({ onProfile: (profile) => console.log(formatProfile(profile)) }));
app.use(express.json());
```

  </TabItem>
  <TabItem label="Development only">

```ts
// src/server.ts
import express from "express";

const app = express();
// A dev dependency: a production install leaves it out, and the app runs without it.
const profiler = await Promise.all([
  import("query-profiler"),
  import("query-profiler/express"),
]).catch(() => undefined);
if (profiler) {
  const [{ formatProfile }, { profilerMiddleware }] = profiler;
  app.use(profilerMiddleware({ onProfile: (profile) => console.log(formatProfile(profile)) }));
}
app.use(express.json());
```

  </TabItem>
</Tabs>

It runs the rest of each request, body parsing and routes included, inside the request's profile,
names the route that answered (`/users/:id`) and serves `/_profiler`.

| Option      | Default      | What it does                                                              |
| ----------- | ------------ | ------------------------------------------------------------------------- |
| `base`      | `/_profiler` | Where the profiler's page and API live. Requests to it are not profiled.  |
| `onProfile` | none         | Called with each profile once its response is sent, to log it or keep it. |

## Seeing what your API did

As with [Fastify](/docs/guides/fastify#seeing-what-your-api-did): the page at `/_profiler`, the
`X-Debug-Token` on each response (open `/_profiler/<token>`), one line per request in the terminal
with `onProfile: (profile) => console.log(formatProfile(profile))`, and the JSON API.

## CORS

When a request comes from another origin, the middleware adds `X-Debug-Token` to
`Access-Control-Expose-Headers`, so a frontend there can read it. If you use `cors` with its own
`exposedHeaders`, add the profiler after it, or list `X-Debug-Token` there too.

## Versions

Before Express 4.18, its body parser drops the request's async context: a route that reads a body
runs outside its profile, and its queries are lost.
